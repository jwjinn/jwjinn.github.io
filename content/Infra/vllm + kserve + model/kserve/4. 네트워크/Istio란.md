쿠버네티스 기본 네트워크(Service)가 단순히 "길을 연결해 주는 도로망"이라면, **Istio는 그 도로 위에 서 있는 "지능형 교통경찰(신호등)"**입니다.

- **정의:** **서비스 메쉬(Service Mesh)** 솔루션의 대명사입니다.
    
- **역할:** 애플리케이션 코드 수정 없이 네트워크 트래픽을 **조종, 보안, 관측**합니다.
    

#### 왜 KServe는 굳이 무거운 Istio를 쓸까요?

KServe가 하려는 고급 기능들이 쿠버네티스 기본 기능만으로는 불가능하기 때문입니다.

1. **똑똑한 라우팅 (Traffic Splitting):** "새 모델(v2)이 나왔으니, 전체 트래픽의 5%만 v2로 보내고 95%는 기존 v1으로 보내" (카나리 배포).
    
2. **보안 (mTLS):** 파드끼리 통신할 때 자동으로 암호화해 줍니다.
    
3. **가시성 (Observability):** "어떤 모델이 응답이 느린지, 에러가 몇 개인지" 신호등에서 다 기록합니다.

### 2. "같은 IP, 다른 목적지"의 비밀 (L4 vs L7)

말씀하신 **"IP는 같은데 헤더를 보고 나눈다"**는 것이 바로 네트워크에서 말하는 **L7(Layer 7) 로드밸런싱**의 핵심입니다.

이 과정을 **택배**로 비유해 볼게요.

#### 1단계: MetalLB (건물 주소 찾기 - L4)

- MetalLB는 **택배 기사님**입니다.
    
- 주소(IP: `192.168.10.50`)만 봅니다.
    
- **"이 박스는 192.168.10.50 건물이네? 일단 건물 로비(Istio Gateway)에 내려놓고 갑니다."**
    
- 박스 안에 뭐가 들었는지, 수신인이 누군지는 관심 없습니다.
    

#### 2단계: Istio (수신인 이름 확인 - L7)

- Istio는 **건물 로비의 안내 데스크 직원**입니다.
    
- 기사님이 두고 간 박스의 **송장(HTTP Header)**을 꼼꼼히 읽습니다.
    
- **"주소는 우리 건물이 맞는데... 수신인(Host Header)이 `qwen`님이시네? 그럼 101호로 가세요."**
    
- **"이 박스는 수신인이 `llama`님이네? 이건 202호로 가세요."**
    

#### 기술적 요약

- **MetalLB:** IP와 포트(TCP)까지만 봅니다. (Layer 4) -> **"어느 컴퓨터로 갈까?"**
    
- **Istio:** HTTP 패킷을 뜯어서 헤더(Host, Path, Cookie 등)를 봅니다. (Layer 7) -> **"어느 서비스(파드)로 갈까?"**
